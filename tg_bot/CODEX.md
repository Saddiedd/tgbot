# CODEX.md

## Назначение проекта

Проект `tg_bot` — Telegram-бот на базе LLM для обучения 3D-моделированию в среде разработки **КОМПАС-3D**.

Тема работы:

> Реализация диалоговой системы на базе LLM с ReAct-агентом для обучения 3D-моделированию в среде разработки КОМПАС-3D.

Бот должен помогать пользователю:
- отвечать на вопросы по API и работе с КОМПАС-3D;
- искать информацию в заранее загруженной базе документов;
- искать актуальную информацию в интернете;
- использовать историю диалога и память;
- работать через интерактивное Telegram-меню;
- демонстрировать логику ReAct-агента: рассуждение → выбор инструмента → действие → ответ.

---

В репозитории основной рабочей папкой является:

```text
tg_bot/
```

Остальные папки репозитория являются вспомогательными и могут использоваться как примеры, но основной код бота должен быть размещён только в `tg_bot`.

Структура должна быть следующей:

```text
tg_bot/
├── .env                    # файл с переменными окружения: токены, ключи API, настройки
├── pyproject.toml          # зависимости и настройки проекта

│   ├── handlers/           # обработчики сообщений, команд и callback-запросов
│   ├── keyboards/          # reply- и inline-клавиатуры
│   └── middlewares/        # промежуточное ПО aiogram
```

Дополнительно разрешается создать внутренние папки, если они нужны для архитектуры:

```text
tg_bot/
├── bot/
```

## Переменные окружения

Все ключи доступа и секретные параметры должны храниться только в файле:

```text
tg_bot/.env
```

Нельзя хардкодить токены и ключи в Python-коде.

Пример `.env`:

```env
TELEGRAM_BOT_TOKEN=your_telegram_bot_token

LLM_PROVIDER=openai
OPENAI_API_KEY=your_openai_api_key
OPENAI_MODEL=gpt-4o-mini

TAVILY_API_KEY=your_tavily_api_key

LANCEDB_PATH=./data/lancedb
LANCEDB_TABLE=kompas_docs

DATABASE_URL=sqlite+aiosqlite:///./data/bot.db

LOG_LEVEL=INFO
```

Если используется другой LLM-провайдер, нужно сохранить принцип: ключи и настройки берутся из `.env`.

## Основные возможности бота

### 1. Общение с пользователем

Бот должен поддерживать:

- команду `/start`;
- команду `/help`;
- команду `/menu`;
- текстовые запросы пользователя;
- интерактивное меню с кнопками;
- inline-кнопки;
- inline-режим Telegram, если он включён у бота.

Примеры режимов меню:

```text
1. Задать вопрос по КОМПАС-3D
2. Найти информацию в документации
3. Найти информацию в интернете
4. Спросить ReAct-агента
5. Очистить историю диалога
6. Справка
```

---

### 2. Поиск по документам

Бот должен уметь искать информацию в базе документов LanceDB.

Пример сценария:

```text
Пользователь:
Как создать документ в КОМПАС-3D через API?

Бот:
1. Выполняет поиск по LanceDB.
2. Находит релевантные фрагменты документации.
3. Передаёт найденный контекст в LLM.
4. Возвращает ответ с пояснением.
```

Поиск по документам должен быть оформлен как отдельный инструмент агента.

Пример названия инструмента:

```text
search_kompas_docs
```

---

### 3. Поиск информации в интернете

Бот должен уметь искать информацию в интернете по запросу пользователя.

Для интернет-поиска использовать Tavily или совместимый сервис.

Поиск в интернете должен быть отдельным инструментом агента.

Пример названия инструмента:

```text
web_search
```

Интернет-поиск использовать, если:
- вопрос требует актуальной информации;
- в локальной базе документов нет ответа;
- пользователь явно просит найти информацию в интернете.

---

### 4. ReAct-агент

В проекте должен быть реализован ReAct-агент.

ReAct-агент должен уметь выбирать между инструментами:

```text
1. search_kompas_docs    # поиск по LanceDB
2. web_search            # поиск в интернете
3. memory_search         # поиск в истории/памяти
4. final_answer          # финальный ответ пользователю
```

Агент должен работать по логике:

```text
Thought: понять задачу пользователя
Action: выбрать инструмент
Observation: получить результат инструмента
Thought: проанализировать результат
Final Answer: ответить пользователю
```

В пользовательский ответ не нужно выводить внутренние рассуждения агента. Пользователь должен видеть только итоговый понятный ответ.

---

### 5. Память и история диалога

Бот должен хранить историю сообщений пользователя.

Минимально допустимый вариант хранения:

```text
SQLite
```

Разрешённые варианты:

```text
SQLite
PostgreSQL
Redis
```

Для учебного проекта лучше использовать SQLite:

```text
tg_bot/data/bot.db
```

История должна позволять:

- сохранять сообщения пользователя;
- сохранять ответы бота;
- очищать историю по команде;
- передавать последние сообщения в LLM как контекст;
- использовать историю в ReAct-агенте.

## Архитектура модулей

### `bot/__main__.py`

Точка входа.

Задачи:

- загрузить конфигурацию;
- создать `Bot`;
- создать `Dispatcher`;
- подключить роутеры;
- подключить middleware;
- запустить polling.

Пример логики:

```python
async def main() -> None:
    config = load_config()
    bot = Bot(token=config.telegram_bot_token)
    dp = Dispatcher()

    dp.include_router(start_router)
    dp.include_router(menu_router)
    dp.include_router(chat_router)
    dp.include_router(inline_router)

    await dp.start_polling(bot)
```

## Обработка запроса пользователя

Основной сценарий обработки текстового сообщения:

```text
Пользователь отправляет сообщение
↓
handler принимает сообщение
↓
сообщение сохраняется в историю
↓
answer_service передаёт запрос ReAct-агенту
↓
агент выбирает инструмент
↓
при необходимости выполняется поиск:
    - в LanceDB
    - в интернете
    - в памяти
↓
LLM формирует итоговый ответ
↓
ответ сохраняется в историю
↓
бот отправляет ответ пользователю
```

## Стиль ответов бота

Бот должен отвечать в учебном стиле:

- простыми словами;
- по шагам;
- с примерами;
- без лишней воды;
- с пояснением команд и кода;
- с акцентом на КОМПАС-3D и 3D-моделирование.

Если пользователь просит код, бот должен давать код и кратко объяснять, куда его вставлять.

Если бот не уверен, он должен явно сказать, что информации недостаточно, и предложить поиск по документации или интернету.

## Inline-режим

Бот должен поддерживать inline-режим.

Пример поведения:

```text
@bot_name как создать деталь в КОМПАС-3D
```

Бот должен вернуть несколько inline-результатов:

```text
1. Ответ по локальной базе
2. Поиск в интернете
3. Запрос к ReAct-агенту
```

Минимально допустимый вариант: один inline-результат с коротким ответом или кнопкой для перехода в чат.

Для разработчика ошибка должна быть записана в лог.
